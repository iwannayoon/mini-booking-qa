# 로그인 보완 요구사항

작성일: 2026-11-02 · 버전: 1.0 · 상태: LR-01~07 전체 확정

## 1. 적용 원칙

[기존 요구사항](requirements.md)의 추가·구체화가 필요한 내용만 기록한다. 보완 이유는 [로그인 요구사항 분석](login-requirements-analysis.md)을 참조한다. 사용자 검토에 따라 LR-01~07을 2026-11-02에 모두 확정했다. LR-02의 로그인 최대 대기 시간은 10초다. 요구사항 확정은 구현 완료나 실행 검증을 뜻하지 않는다.

기존 R-01~R-04와 N-02는 유지한다. 확정 항목의 안내 문구와 동작은 수용 기준으로 사용한다. LR-02·06·07의 최대 대기 시간은 모두 10초로 확정한다. 구현·자동화·실행 상태는 정책 확정 상태와 별도로 관리한다.

## 2. 보완 요구사항과 수용 기준

### LR-01. 로그인 네트워크 실패

- 연결: R-02 / A-L01 · 상태: 확정 (2026-11-02)
- 로그인 요청이 연결 끊김 등으로 유효한 응답을 받지 못하면 “연결에 문제가 발생했습니다. 연결 상태를 확인한 뒤 다시 시도해 주세요.”를 표시한다.
- 로그인 성공 화면으로 전환하지 않는다. 계정과 비밀번호 입력값을 현재 화면에 유지하고 처리 중 상태를 해제한다.
- 자동으로 재요청하지 않는다. 사용자가 다시 제출할 수 있어야 한다.
- 응답을 받지 못했다고 서버에 세션이 생성되지 않았다고 단정하지 않는다. 테스트 기대 결과에서 서버의 세션 미생성을 요구하지 않는다.

### LR-02. 로그인 응답 시간 초과

- 연결: R-02 / A-L02 · 상태: 확정 (2026-11-02)
- 요청 시작 후 10초 이내에 처리가 완료되지 않으면 대기를 종료하고 “응답이 지연되고 있습니다. 잠시 후 다시 시도해 주세요.”를 표시한다.
- 입력값을 유지하고 다시 제출할 수 있도록 한다. 종료된 요청의 늦은 결과로 화면 상태를 변경하지 않는다.
- 클라이언트의 대기 종료가 서버 처리 취소나 세션 미생성을 보장하지는 않는다.
- 확정 사항: 로그인 요청의 최대 대기 시간은 10초(10,000ms)다. 이는 정상 응답의 목표 시간이 아니라 실패 판단을 위한 최대 대기 시간이다.
- 참고: [Auth0 Vue SDK 문서](https://auth0.github.io/auth0-vue/interfaces/Auth0VueClientOptions.html)의 `httpTimeoutInSeconds` 기본값은 10초다. 인증 SDK의 HTTP 요청 설정 사례이며, 모든 서비스의 로그인 화면 전체 제한 시간을 뜻하지 않는다. [NN/g 응답 시간 지침](https://www.nngroup.com/articles/response-times-3-important-limits/)은 약 10초를 사용자가 대화에 주의를 유지하는 한계로 설명한다. 이 역시 로그인 타임아웃 표준은 아니다.
- 판단: 외부 인증·MFA가 없는 현재 로컬 데모에는 10초를 적용한다. 15초도 정책으로 선택할 수 있으나, 실제 지연 데이터 없이 더 적절하다고 단정하지 않는다.

### LR-03. 서버 오류 및 예상하지 못한 응답

- 연결: R-02 / A-L03 · 상태: 확정 (2026-11-02)
- 로그인 API의 5xx, JSON으로 해석할 수 없는 응답, 200 응답에 유효한 사용자 이름·역할이 없는 경우를 대상으로 한다.
- “로그인 처리 중 문제가 발생했습니다. 잠시 후 다시 시도해 주세요.”를 표시한다. 내부 예외나 서버 응답 원문을 사용자 안내로 그대로 표시하지 않는다.
- 로그인 성공으로 처리하지 않고, 입력값을 유지하며 처리 중 상태를 해제한다.
- 인증 실패 401은 기존의 “계정 또는 비밀번호를 확인해 주세요.”로 구분한다. 이 항목은 모든 4xx 응답을 인증 실패로 간주하는 정책이 아니다.

### LR-04. 로그인 중복 요청 방지

- 연결: R-02 / A-L04 · 상태: 확정 (2026-11-02)
- 유효한 입력으로 요청을 시작하면 로그인 버튼을 비활성화하고 “로그인 중…”을 표시한다.
- 해당 요청이 완료되거나 시간 초과될 때까지 클릭·Enter·반복 제출로 추가 로그인 요청을 보내지 않는다.
- 실패·시간 초과 후 버튼을 활성화하고 “로그인”으로 복원한다. 성공하면 사용자 이름·역할과 로그인 후 화면을 표시한다.
- 필수 입력 오류로 요청하지 않은 경우에는 처리 중 상태로 진입하지 않는다.

### LR-05. 로그아웃 성공 및 반복 호출

- 연결: R-03, R-04 / A-L05 · 상태: 확정 (2026-11-02)
- 로그인한 사용자에게 로그아웃 버튼을 제공한다. 요청 처리 중에는 버튼을 비활성화하고 중복 요청을 차단한다.
- 정상 요청에 서버는 200과 `{ "ok": true }`를 반환하고 해당 세션과 세션 쿠키를 제거한다.
- 성공 응답 후 로그인 화면으로 이동하며 사용자 표시, 예약 목록, 선택한 시간, 열린 모달 등 이전 사용자에 속한 화면 상태를 초기화한다. 예약 데이터 자체를 삭제하거나 취소하지 않는다.
- 새로고침해도 비로그인 상태를 유지한다. 제거된 세션으로 /api/me와 보호 API를 호출하면 401을 반환한다.
- 유효 세션이 없는 정상 로그아웃 요청도 200으로 처리한다. 기존 Origin 검증 등 공통 요청 정책은 계속 적용한다.

### LR-06. 로그아웃 실패 및 결과 불명

- 연결: R-03 / A-L06 · 상태: 확정 (2026-11-02)
- 네트워크 실패, 10초 시간 초과, 5xx 또는 예상하지 못한 응답이면 “로그아웃 완료를 확인하지 못했습니다. 다시 시도해 주세요.”를 표시한다.
- 처리 중 상태를 해제하고 재시도를 허용한다. 성공 안내나 로그아웃 완료 화면 전환을 하지 않는다.
- 성공 확인 전에는 현재 화면을 유지하되, 이것이 서버 세션의 유효성을 보장한다는 뜻은 아니다. 서버가 이미 세션을 제거했을 수도 있다.
- 이후 보호 API에서 401이 확인되면 LR-07에 따라 비로그인 상태로 전환한다. 로그아웃 재요청은 LR-05의 반복 호출 정책을 따른다.
- 확정 사항: 실패 시 현재 화면 유지와 10초 대기 한계를 적용한다.

### LR-07. 세션 복원 실패와 사용 중 세션 소멸

- 연결: R-03, R-04 / A-L07 · 상태: 확정 (2026-11-02)
- 최초 /api/me 조회에서 200과 유효한 사용자 정보가 오면 해당 사용자로 복원한다. 401이면 정상적인 비로그인 상태로 보고 로그인 화면을 표시한다.
- 최초 조회의 네트워크 실패·5xx·응답 형식 오류·10초 시간 초과는 401과 구분하여 “로그인 상태를 확인하지 못했습니다. 다시 시도해 주세요.”와 세션 확인 재시도 동작을 제공한다. 확인 중에는 보호된 화면과 로그인 제출을 활성화하지 않는다.
- 로그인 상태로 이용 중 보호 API가 401을 반환하면 이전 사용자 화면 상태를 초기화하고 로그인 화면에 “로그인이 필요합니다. 다시 로그인해 주세요.”를 표시한다.
- 다른 사용자로 재로그인해도 이전 사용자의 예약 목록이나 선택 상태를 표시하지 않는다. 완료가 늦어진 이전 요청으로 이전 사용자 데이터를 다시 표시하지 않는다.
- 서버 재시작 후에도 같은 규칙을 적용한다. 세션 만료 시간이나 다른 탭의 즉각적인 동기화는 이번 보완에서 새로 정의하지 않는다.
