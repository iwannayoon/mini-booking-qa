# 로그인 요구사항 분석

작성일: 2026-11-02 · 상태: 분석 완료 (작성 시점 기록)

## 1. 목적과 문서 관계

로그인 기능을 대상으로 기존 명세에서 검증 조건을 도출하고, 누락되거나 모호한 정책을 찾아 보완한다. 이후 테스트 케이스, 자동화 코드, 실행 리포트에 요구사항 ID를 연결한다. 예약 기능은 후속 범위다.

- 기준 문서: [기존 요구사항](requirements.md). 이번 작업에서는 변경하지 않았다.
- 분석 결과: 이 문서의 A-L 항목.
- 보완 정책: [로그인 보완 요구사항](login-requirements-supplement.md)의 LR 항목. LR-01~07은 2026-11-02 사용자 검토로 모두 확정했으며, LR-02의 로그인 최대 대기 시간은 10초다. 기존 명세와 함께 읽는다.
- 근거 코드: [화면](../src/main.jsx), [API](../server/app.js), [로그인 E2E](../tests/login.e2e.spec.js).

현재 구현에 대한 설명은 소스 확인 결과다. 이번 문서 작업에서는 테스트를 실행하지 않았으며 실행 성공이나 결함 재현을 의미하지 않는다. 기존 명세 자체도 구현을 대조해 작성된 현행 명세이므로, 최초 사업 요구사항으로 표현하지 않는다.

## 2. 기존 요구사항에서 도출한 검증 조건

| 기준 ID | 검증 조건                                                        | 분석 관점                            |
| ----- | ------------------------------------------------------------ | -------------------------------- |
| R-01  | 초기 입력값은 비어 있음. 계정만 빈 값, 비밀번호만 빈 값, 둘 다 빈 값, 공백만 있는 계정        | 동등 분할: 유효 입력과 필수 입력 오류를 분리       |
| R-01  | 항목별 오류 문구·강조, 첫 오류 필드 포커스, 요청 미전송, 입력 후 해당 오류 해제             | 오류 표시뿐 아니라 요청 차단과 오류 복구까지 확인     |
| R-02  | alice/bob/admin 정상 인증 및 이름·역할. 없는 계정, 틀린 비밀번호, 대소문자·앞뒤 공백 차이 | 인증 성공과 실패를 분리. 실패 원인을 하나씩 바꾸어 검증 |
| R-03  | 로그인 후 새로고침 시 사용자 복원, 로그아웃 시 세션 제거·로그인 화면 이동, 서버 재시작 시 세션 소멸  | 비로그인 → 로그인 → 비로그인 상태 전이          |
| R-04  | 비로그인 상태와 로그아웃 후 보호 API의 401                                  | 화면 전환과 서버 접근 차단을 각각 확인           |
| N-02  | 세션 쿠키 속성, 다른 Origin의 상태 변경 요청 거부                             | 인증 관련 API 검증에 연결할 기존 보안 조건       |

계정의 공백만 있는 값은 R-01에서 요청을 차단하지만, ` alice `는 R-02에 따라 인증 실패 대상이다. 비밀번호 공백 문자열은 빈 문자열과 구분하며, 현재 명세에서 자동으로 trim한다는 정책을 가정하지 않는다.

## 3. 누락·모호함과 보완 방향

| 분석 ID | 기준 | 발견 내용과 영향 | 보완 연결 |
|---|---|---|---|
| A-L01 | R-02 | 네트워크 연결 실패 시 안내·입력 보존·재시도 정책이 없다. 사용자가 인증 오류와 연결 장애를 혼동할 수 있다. | LR-01 |
| A-L02 | R-02 | 응답 지연의 대기 한계가 없다. 처리 중 상태가 계속될 수 있다. | LR-02 |
| A-L03 | R-02 | ‘알 수 없는 오류’의 범위가 불명확하다. 5xx, JSON 파싱 실패, 성공 응답의 필수 필드 누락을 구분해 재현 조건을 정의해야 한다. | LR-03 |
| A-L04 | R-02 | 처리 중 중복 클릭·Enter 제출과 완료 후 복구 정책이 없다. 중복 인증 요청 가능성을 확인해야 한다. | LR-04 |
| A-L05 | R-03, R-04 | 로그아웃 성공은 명시되어 있으나 쿠키 처리, 재호출, 이후 API 접근의 상세 기준이 부족하다. | LR-05 |
| A-L06 | R-03 | 로그아웃 실패 시 안내와 재시도 정책이 없다. 응답이 유실되면 서버에서 세션이 삭제됐는지도 확정할 수 없다. | LR-06 |
| A-L07 | R-03, R-04 | 초기 세션 확인의 401과 통신 장애, 사용 중 세션 소멸을 화면에서 어떻게 구분할지 명시되지 않았다. | LR-07 |
| A-L08 | R-01, R-02 | 대소문자·공백 구분은 명시되어 있다. 편의상 정규화하도록 임의 변경하면 기존 명세와 충돌한다. | 기존 정책 유지. 변경 필요 시 별도 결정 |

## 4. 현재 구현과 자동화에서 확인한 범위

> 2026-11-02 분석 시점의 코드 확인 결과다. 이후 보완 요구사항이 구현·자동화되었으며, 현재 결과는 [로그인 테스트 리포트](login-test-report.md)를 따른다.

| 영역 | 소스에서 확인한 동작 | 남은 확인 |
|---|---|---|
| 로그인 오류 | API helper가 JSON을 읽고 오류를 던지며, 화면은 예외의 message를 표시 | 네트워크·파싱 오류의 공통 사용자 문구, 성공 응답 구조 검증은 명시적으로 구현되어 있지 않음 |
| 로그인 처리 중 | busy 상태로 로그인 버튼 비활성화, finally에서 해제 | 명시적 요청 시간 제한과 submit 핸들러의 중복 실행 차단은 없음. 실제 중복 요청 여부는 별도 검증 필요 |
| 로그아웃 성공 | 서버 세션 삭제·쿠키 제거. 응답 성공 후 화면의 사용자·선택 상태 초기화 | 이전 세션으로 보호 API 호출 시 401 및 재호출 동작 검증 필요 |
| 로그아웃 실패 | 클릭 핸들러에 별도 catch와 처리 중 차단이 없음 | 사용자 안내·재시도 및 결과 불명 상태 정책 보완 필요 |
| 초기 세션 확인 | /api/me 성공 시 사용자 복원, 실패는 catch에서 무시 | 401과 네트워크·서버 장애를 구분하는 안내 보완 필요 |
| 로그인 E2E | 필수 입력 오류, 잘못된 인증 정보 안내, alice 로그인 후 이름·역할·로그아웃 버튼 검증 코드 존재 | 공백, 포커스, 요청 미전송, 오류 해제, 다른 계정, 세션·로그아웃·장애 상황 등의 개별 검증 필요 |

기존 테스트 시나리오 문서(현재는 보관)는 과거 작성 시점의 상태를 포함한다. 특히 로그인 E2E 관련 현황은 현재 코드와 다시 대조해야 하며, 이 문서의 코드 확인 결과도 실행 리포트로 사용하지 않는다.

## 5. 다음 단계

> 아래 단계는 모두 진행되었다: [로그인 테스트 케이스](login-test-cases.md) → 테스트 자동화 → [로그인 테스트 리포트](login-test-report.md).

1. 확정된 LR-01~07을 테스트 설계 기준으로 사용한다. 로그인·로그아웃·세션 확인의 최대 대기 시간은 모두 10초다.
2. 기존 요구사항과 확정된 보완 요구사항에서 로그인 테스트 케이스를 도출한다. 아직 제안인 정책은 테스트 설계 초안으로 구분한다.
3. 케이스별 요구사항 ID, 사전조건, 입력, 절차, 기대 결과, 우선순위, API/E2E 선택 이유를 기록한다.
4. 기존 자동화와 연결하여 구현됨·부분 구현·미구현을 구분한다.
5. 실행 후 환경·실행 일시·결과·증거를 별도 리포트에 기록한다. 제안과 구현의 차이를 곧바로 확정 결함으로 판정하지 않는다.

포트폴리오의 전체 순서는 프로젝트 소개 → 요구사항 정리 → 요구사항 분석 → 테스트 케이스 → 자동화 → 테스트 리포트로 유지한다.
