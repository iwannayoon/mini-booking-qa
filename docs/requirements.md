# 예약 서비스 요구사항 명세서

작성 기준: 2026-09-21. README, 설계 문서, 현재 UI·API·DB 구현을 대조하여 작성한 현행 명세이다. 별도로 승인된 사업 요구사항이나 실행 검증 결과를 뜻하지 않는다.

## 1. 목적과 범위

QA 자동화 학습과 포트폴리오를 위한 로컬 스터디룸 예약 서비스다. 기능 확장보다 사용자 흐름, 권한, 상태 전이, 데이터 무결성의 테스트 설계가 목적이다.

- 공간: 포커스 룸 1개. 최대 4인은 안내 문구이며 인원 입력·검증 기능은 없다.
- 사용자: 일반 사용자 alice, bob과 관리자 admin. 모두 비밀번호는 demo1234이다.
- 포함: 로그인·로그아웃, 시간 조회·선택, 단일·복수 예약, 본인 이력 조회·취소, 관리자 잠금.
- 제외: 회원가입, 실제 결제, 여러 룸, 반복 예약, 알림, 운영용 인증, 다중 서버 부하 보장.

## 2. 기능 요구사항

| ID   | 영역        | 요구사항 및 수용 기준                                                                                                                                                                               |
| ---- | --------- | ------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------ |
| R-01 | 로그인 입력    | 계정과 비밀번호의 초기값은 빈 값이며 둘 다 필수다. 빈 상태로 제출하면 기본 브라우저 안내 대신 입력란을 강조하고 하단에 '계정을 입력해주세요.' 또는 '비밀번호를 입력해주세요.'를 표시한다. 첫 오류 입력란으로 포커스를 이동하고 요청은 보내지 않는다. 입력을 채우면 해당 오류를 해제한다. 공백만 있는 계정도 빈 값으로 처리한다. |
| R-02 | 인증        | alice/bob/admin과 정확한 비밀번호로 로그인하면 200과 사용자 이름·역할을 반환한다. 그 외 조합은 401과 오류 안내를 반환한다. 현재 계정 비교는 대소문자·공백을 그대로 구분한다.                                                                              |
| R-03 | 세션        | 로그인 후 새로고침해도 같은 세션에서 사용자 정보를 복원한다. 로그아웃하면 세션을 제거하고 로그인 화면으로 돌아간다. 서버 재시작 시 메모리 세션은 소멸한다.                                                                                                   |
| R-04 | 접근 권한     | 미인증 사용자의 시간·예약 조회, 예약·취소, 관리자 API 접근은 401이다. 인증된 일반 사용자의 관리자 API 접근은 403이다. 본인 예약만 조회하며 타인 또는 없는 예약 ID 취소는 404이다.                                                                          |
| R-05 | 시간 규칙     | KST 기준 09:00부터 17:00까지 정각 시작의 1시간 슬롯 9개를 제공한다. 예약 시작 시각은 현재보다 미래이고 현재부터 30×24시간 미만이어야 한다. 정확히 현재 또는 30일 후인 시작 시각은 불가하다.                                                                    |
| R-06 | 날짜·가용성    | 화면 최초 선택 날짜는 KST 내일이다. 시간 경계 밖, 확정 예약 존재, 관리자 잠금 상태인 슬롯은 예약 불가로 표시하고 선택을 비활성화한다.                                                                                                           |
| R-07 | 시간 선택     | 같은 날짜에서 여러 슬롯을 선택·해제할 수 있다. 선택 상태는 aria-pressed로 표현한다. 선택만으로 예약이 생성되지 않는다. 선택이 없거나 처리 중이면 예약 확정 버튼은 비활성화된다.                                                                                |
| R-08 | 예약 요약     | 공간, 날짜, 시간 범위, 총 시간, 시간당 10,000원과 총 데모 금액을 표시한다. 연속 시간은 묶고 떨어진 시간은 분리한다. 실제 결제는 없다.                                                                                                        |
| R-09 | 날짜 변경     | 선택한 시간이 있으면 확인 모달을 표시한다. 돌아가기는 기존 날짜·선택을 유지하고, 확인은 선택을 지우고 새 날짜로 이동한다. 선택이 없으면 바로 이동한다.                                                                                                    |
| R-10 | 예약 생성     | 단일 slot 또는 같은 날짜의 slots 배열을 받아 201로 생성한다. 배열은 1~9개이고 중복이 없어야 한다. 잘못된 형식·시간·날짜·배열은 400이다. 생성 상태는 confirmed이다.                                                                               |
| R-11 | 충돌·원자성    | 같은 슬롯에는 확정 예약이 최대 1건이다. 이미 예약되거나 잠긴 슬롯 예약은 409이다. 복수 예약 중 하나라도 충돌하면 전체를 롤백한다. 경쟁하는 두 유효 요청에서는 성공 1건과 충돌 1건이어야 한다.                                                                          |
| R-12 | 생성 결과     | 성공하면 완료 안내, 선택 초기화, 가용 시간과 내 예약 갱신을 수행한다. 예약 요청 실패 시 오류를 안내하고 선택·요약을 유지하며 처리 상태를 해제한다. 성공 후 목록 갱신만 실패하면 성공 사실과 새로고침 안내를 함께 표시한다.                                                           |
| R-13 | 내 예약      | 본인의 확정·취소 이력을 표시한다. 같은 날짜·같은 상태의 연속 슬롯은 하나의 카드로 묶고, 비연속 슬롯은 분리한다. 새로고침 후에도 저장된 예약을 확인할 수 있다.                                                                                               |
| R-14 | 취소 확인 UI  | 확정 카드에서 취소를 누르면 대상 일시·총 시간과 묶음 취소 안내를 표시한다. 돌아가기는 예약을 유지한다. 확인 시 해당 카드의 모든 예약을 취소한다. 실패하면 모달 내 오류를 표시한다.                                                                                   |
| R-15 | 취소 API    | 본인 단일 예약 및 ids 배열(중복 없는 문자열 1~9개)을 취소한다. 잘못된 배열은 400이다. 묶음에 타인·없는 ID가 포함되면 404이며 전체 취소를 수행하지 않는다. 이미 취소한 예약의 재취소도 성공한다.                                                                    |
| R-16 | 취소 이력·재예약 | 상태는 confirmed → cancelled로 변경하며 행을 삭제하지 않는다. 취소된 카드의 일시·공간·총 시간은 회색 취소선으로 표시한다. 취소 후 시간 조건을 만족하고 잠기지 않은 슬롯은 다시 예약할 수 있다.                                                                   |
| R-17 | 관리자       | 관리자에게만 잠금·해제 버튼을 표시한다. 유효한 빈 슬롯을 잠그고 해제할 수 있다. 이미 확정 예약이 있는 슬롯의 잠금은 409이며 기존 예약은 유지한다. 슬롯 또는 blocked 타입이 잘못되면 400이다.                                                                       |

## 3. 저장·환경 요구사항

2026-09-28 추가: 신규 예약 ID는 생성일(KST) YYYYMMDD와 날짜별 공통 순번을 연결한 `20260928-0001` 형태다. 슬롯마다 발급하며 순번은 최소 4자리다. 취소·서버 재시작에도 순번을 유지하고 예약 실패 시 발급을 롤백한다. 기존 UUID는 유지한다. 상세는 [설계 문서](design.md)의 예약 저장과 ID를 참조한다.

| ID | 요구사항 및 수용 기준 |
|---|---|
| N-01 | SQLite에 예약과 잠금을 저장한다. 서버 재시작 후 데이터는 유지한다. 부분 고유 인덱스가 동일 슬롯의 confirmed 중복을 방지한다. |
| N-02 | 세션 쿠키는 HttpOnly와 SameSite=Strict를 사용한다. Origin 헤더가 있는 상태 변경 요청은 서버가 기대하는 동일 Origin과 다르면 403으로 거부한다. |
| N-03 | 일반 서비스는 기본 3000 포트, 자동화는 3100 포트와 실행별 임시 DB를 사용한다. worker는 1개, 자동 재시도는 0회이며 실패 보고서·trace·스크린샷을 설정한다. |

## 4. 주요 API

| 메서드·경로 | 입력 | 정상 응답 |
|---|---|---|
| POST /api/login | username, password | 200, 사용자 객체 |
| POST /api/logout | 없음 | 200, ok |
| GET /api/me | 세션 쿠키 | 200, 사용자 객체 |
| GET /api/slots?date=YYYY-MM-DD | 날짜 | 200, 슬롯·available·blocked 배열 |
| GET /api/bookings | 세션 쿠키 | 200, 본인 예약 배열 |
| POST /api/bookings | slot 또는 slots | 201, 단일 객체 또는 배열 |
| POST /api/bookings/:id/cancel | 예약 ID | 200, 취소된 예약 객체 |
| POST /api/bookings/cancel | ids | 200, ok |
| PUT /api/admin/slots | slot, blocked(boolean) | 200, slot·blocked |

## 5. 해석 주의·후속 결정 사항

- 화면의 '30일 이내'는 설명 문구다. 실제 API 규칙은 시작 시각 기준의 엄격한 30일 미만이다.
- 시간 조회 API는 날짜 문자열 형식이 잘못되면 400이다. 형태만 맞는 존재하지 않는 날짜는 현재 구현에서 200과 예약 불가 슬롯으로 처리한다. 예약 생성 API에서는 유효하지 않은 날짜를 400으로 거부한다.
- 취소에는 현재 별도 시간 제한이 없다. 과거 예약 취소를 막는 정책을 가정하지 않는다.
- 선택 가능한 시간은 실시간 push로 갱신되지 않는다. 두 사용자가 같은 슬롯을 선택한 상태가 가능하며 확정 시 API에서 충돌을 판정한다.
- 단일 Node 프로세스의 동기 DB 작업은 순차 처리된다. 경쟁 요청 테스트는 중복 방지 검증이며 다중 서버 성능 검증은 아니다.
- '현재부터 가까운 최대 3시간 자동 선택'은 논의만 한 별도 시나리오이며 현재 서비스 요구사항에 추가하지 않았다.
