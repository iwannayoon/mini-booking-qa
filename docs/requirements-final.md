# 예약 서비스 요구사항 명세서 최종본

통합일: 2026-11-07 · 버전: 1.0

[기존 요구사항](requirements.md)과 [확정된 로그인 보완 요구사항](login-requirements-supplement.md)을 한곳에서 읽기 위한 최종 통합본이다. 기존 문서는 분석·결정 이력으로 보존한다. 기존 명세는 구현을 대조하여 작성된 현행 명세이고, 로그인 보완 정책은 2026-11-02 사용자 검토로 확정되었다. 이 문서는 구현 완료나 테스트 통과를 의미하지 않는다.

## 1. 목적과 범위

QA 자동화 학습과 포트폴리오를 위한 로컬 스터디룸 예약 서비스다. 기능 확장보다 사용자 흐름, 권한, 상태 전이, 데이터 무결성의 테스트 설계가 목적이다.

- 공간: 포커스 룸 1개. 최대 4인은 안내 문구이며 인원 입력·검증 기능은 없다.
- 사용자: 일반 사용자 alice, bob과 관리자 admin. 모두 비밀번호는 demo1234이다.
- 포함: 로그인·로그아웃, 시간 조회·선택, 단일·복수 예약, 본인 이력 조회·취소, 관리자 잠금.
- 제외: 회원가입, 실제 결제, 여러 룸, 반복 예약, 알림, 운영용 인증, 다중 서버 부하 보장.

## 2. 요구사항 한눈에 보기

| 영역           | 통합 ID   | 주요 내용                              |
| ------------ | ------- | ---------------------------------- |
| 로그인          | R-01~06 | 필수 입력, 인증, 중복 요청, 네트워크·시간 초과·서버 오류 |
| 세션·로그아웃·권한   | R-07~10 | 세션 복원, 로그아웃 성공·실패, 접근 제한           |
| 시간 선택·예약     | R-11~18 | 시간 규칙, 가용성, 선택·요약, 생성·충돌·결과        |
| 예약 이력·취소·관리자 | R-19~23 | 내 예약, 취소·재예약, 관리자 잠금               |
| 저장·환경        | N-01~04 | 데이터 유지, 쿠키·Origin, 실행 환경, 예약 ID    |

로그인·로그아웃·초기 세션 확인의 최대 대기 시간은 모두 **10초(10,000ms)**다. 정상 응답의 목표 시간이 아닌, 응답 없는 요청의 대기를 종료하는 기준이다.

## 3. 기능 요구사항 및 수용 기준
### 3-1. 로그인 및 인증
#### `R-01` 계정 및 비밀번호 입력

- 계정과 비밀번호의 초기값은 빈 값이며 둘 다 필수다.
- 빈 상태로 제출하면 기본 브라우저 안내 대신 입력란을 강조하고 하단에 '계정을 입력해주세요.' 또는 '비밀번호를 입력해주세요.'를 표시한다.
	- 첫 오류 입력란으로 포커스를 이동하고 요청은 보내지 않는다.
	- 입력을 채우면 해당 오류를 해제한다.
- 공백만 있는 계정도 빈 값으로 처리한다.

#### `R-02` 인증 성공·실패

- 정확한 계정과 비밀번호로 로그인하면 200과 사용자 이름·역할을 반환한다.
- 그 외 조합은 401과 오류 안내를 반환한다.
- 현재 계정 비교는 대소문자·공백을 그대로 구분한다.
#### `R-03` 로그인 처리 중·중복 요청

- 유효한 입력으로 요청을 시작하면 로그인 버튼을 비활성화하고 “로그인 중…”을 표시한다.
- 해당 요청이 완료되거나 시간 초과될 때까지 클릭·Enter·반복 제출로 추가 로그인 요청을 보내지 않는다.
- 실패·시간 초과 후 버튼을 활성화하고 “로그인”으로 복원한다. 성공하면 사용자 이름·역할과 로그인 후 화면을 표시한다.
- 필수 입력 오류로 요청하지 않은 경우에는 처리 중 상태로 진입하지 않는다.

#### `R-04` 로그인 네트워크 실패

- 로그인 요청이 연결 끊김 등으로 유효한 응답을 받지 못하면 “연결에 문제가 발생했습니다. 연결 상태를 확인한 뒤 다시 시도해 주세요.”를 표시한다.
- 로그인 성공 화면으로 전환하지 않는다. 계정과 비밀번호 입력값을 현재 화면에 유지하고 처리 중 상태를 해제한다.
- 자동으로 재요청하지 않는다. 사용자가 다시 제출할 수 있어야 한다.
- 응답을 받지 못했다고 서버에 세션이 생성되지 않았다고 단정하지 않는다. 테스트 기대 결과에서 서버의 세션 미생성을 요구하지 않는다.

#### `R-05` 로그인 응답 시간 초과

- 요청 시작 후 10초 이내에 처리가 완료되지 않으면 대기를 종료하고 “응답이 지연되고 있습니다. 잠시 후 다시 시도해 주세요.”를 표시한다.
- 입력값을 유지하고 다시 제출할 수 있도록 한다. 종료된 요청의 늦은 결과로 화면 상태를 변경하지 않는다.
- 클라이언트의 대기 종료가 서버 처리 취소나 세션 미생성을 보장하지는 않는다.
- 확정 사항: 로그인 요청의 최대 대기 시간은 10초(10,000ms)다. 이는 정상 응답의 목표 시간이 아니라 실패 판단을 위한 최대 대기 시간이다.

#### `R-06` 서버 오류·예상하지 못한 응답

- 로그인 API의 5xx, JSON으로 해석할 수 없는 응답, 200 응답에 유효한 사용자 이름·역할이 없는 경우를 대상으로 한다.
- “로그인 처리 중 문제가 발생했습니다. 잠시 후 다시 시도해 주세요.”를 표시한다. 내부 예외나 서버 응답 원문을 사용자 안내로 그대로 표시하지 않는다.
- 로그인 성공으로 처리하지 않고, 입력값을 유지하며 처리 중 상태를 해제한다.
- 인증 실패 401은 기존의 “계정 또는 비밀번호를 확인해 주세요.”로 구분한다. 이 항목은 모든 4xx 응답을 인증 실패로 간주하는 정책이 아니다.

#### `R-07` 세션 복원·소멸

- 로그인 후 새로고침해도 유효한 같은 세션의 사용자 정보를 복원한다. 서버 재시작 시 메모리 세션은 소멸한다.
- 최초 /api/me 조회에서 200과 유효한 사용자 정보가 오면 해당 사용자로 복원한다. 401이면 정상적인 비로그인 상태로 보고 로그인 화면을 표시한다.
- 최초 조회의 네트워크 실패·5xx·응답 형식 오류·10초 시간 초과는 401과 구분하여 “로그인 상태를 확인하지 못했습니다. 다시 시도해 주세요.”와 세션 확인 재시도 동작을 제공한다. 확인 중에는 보호된 화면과 로그인 제출을 활성화하지 않는다.
- 로그인 상태로 이용 중 보호 API가 401을 반환하면 이전 사용자 화면 상태를 초기화하고 로그인 화면에 “로그인이 필요합니다. 다시 로그인해 주세요.”를 표시한다.
- 다른 사용자로 재로그인해도 이전 사용자의 예약 목록이나 선택 상태를 표시하지 않는다. 완료가 늦어진 이전 요청으로 이전 사용자 데이터를 다시 표시하지 않는다.
- 서버 재시작 후에도 같은 규칙을 적용한다. 세션 만료 시간이나 다른 탭의 즉각적인 동기화는 이번 보완에서 새로 정의하지 않는다.

#### `R-08` 로그아웃 성공·반복 호출

- 로그인한 사용자에게 로그아웃 버튼을 제공한다. 요청 처리 중에는 버튼을 비활성화하고 중복 요청을 차단한다.
- 정상 요청에 서버는 200과 `{ "ok": true }`를 반환하고 해당 세션과 세션 쿠키를 제거한다.
- 성공 응답 후 로그인 화면으로 이동하며 사용자 표시, 예약 목록, 선택한 시간, 열린 모달 등 이전 사용자에 속한 화면 상태를 초기화한다. 예약 데이터 자체를 삭제하거나 취소하지 않는다.
- 새로고침해도 비로그인 상태를 유지한다. 제거된 세션으로 /api/me와 보호 API를 호출하면 401을 반환한다.
- 유효 세션이 없는 정상 로그아웃 요청도 200으로 처리한다. 기존 Origin 검증 등 공통 요청 정책은 계속 적용한다.

#### `R-09` 로그아웃 실패·결과 불명

- 네트워크 실패, 10초 시간 초과, 5xx 또는 예상하지 못한 응답이면 “로그아웃 완료를 확인하지 못했습니다. 다시 시도해 주세요.”를 표시한다.
- 처리 중 상태를 해제하고 재시도를 허용한다. 성공 안내나 로그아웃 완료 화면 전환을 하지 않는다.
- 성공 확인 전에는 현재 화면을 유지하되, 이것이 서버 세션의 유효성을 보장한다는 뜻은 아니다. 서버가 이미 세션을 제거했을 수도 있다.
- 이후 보호 API에서 401이 확인되면 `R-07`에 따라 비로그인 상태로 전환한다. 로그아웃 재요청은 `R-08`의 반복 호출 정책을 따른다.
- 확정 사항: 실패 시 현재 화면 유지와 10초 대기 한계를 적용한다.

#### `R-10` 접근 권한

- 미인증 사용자의 시간·예약 조회, 예약·취소, 관리자 API 접근은 401이다.
- 인증된 일반 사용자의 관리자 API 접근은 403이다.
- 본인 예약만 조회하며 타인 또는 없는 예약 ID 취소는 404이다.


### 3-2. 예약
#### `R-11` 시간 규칙

- KST 기준 09:00부터 17:00까지 정각 시작의 1시간 슬롯 9개를 제공한다.
- 예약 시작 시각은 현재보다 미래이고 현재부터 30×24시간 미만이어야 한다.
- 정확히 현재 또는 30일 후인 시작 시각은 불가하다.
#### `R-12` 날짜·가용성

- 화면 최초 선택 날짜는 KST 내일이다.
- 시간 경계 밖, 확정 예약 존재, 관리자 잠금 상태인 슬롯은 예약 불가로 표시하고 선택을 비활성화한다.
- 시간 조회 API는 날짜가 `YYYY-MM-DD` 형식이 아니면 400을 반환한다. 형식은 맞지만 존재하지 않는 날짜이면 200과 모든 슬롯의 `available=false`를 반환한다.
- 가용 시간은 실시간 push로 갱신되지 않는다. 두 사용자가 같은 슬롯을 선택할 수 있으며, 예약 확정 요청 시 서버가 충돌을 판정한다.

#### `R-13` 시간 선택

- 같은 날짜에서 여러 슬롯을 선택·해제할 수 있다.
- 선택 상태는 aria-pressed로 표현한다.
- 선택만으로 예약이 생성되지 않는다.
- 선택이 없거나 처리 중이면 예약 확정 버튼은 비활성화된다.

#### `R-14` 예약 요약

- 공간, 날짜, 시간 범위, 총 시간, 시간당 10,000원과 총 데모 금액을 표시한다.
- 연속 시간은 묶고 떨어진 시간은 분리한다.
- 실제 결제는 없다.

#### `R-15` 날짜 변경

- 선택한 시간이 있으면 확인 모달을 표시한다.
- 돌아가기는 기존 날짜·선택을 유지하고, 확인은 선택을 지우고 새 날짜로 이동한다.
- 선택이 없으면 바로 이동한다.

#### `R-16` 예약 생성

- 단일 slot 또는 같은 날짜의 slots 배열을 받아 201로 생성한다.
- 배열은 1~9개이고 중복이 없어야 한다.
- 잘못된 형식·시간·날짜·배열은 400이다. 존재하지 않는 날짜도 시간 조회 API와 달리 예약 생성 API에서는 400으로 거부한다.
- 생성 상태는 confirmed이다.

#### `R-17` 충돌·원자성

- 같은 슬롯에는 확정 예약이 최대 1건이다.
- 이미 예약되거나 잠긴 슬롯 예약은 409이다.
- 복수 예약 중 하나라도 충돌하면 전체를 롤백한다.
- 경쟁하는 두 유효 요청에서는 성공 1건과 충돌 1건이어야 한다.

#### `R-18` 생성 결과

- 성공하면 완료 안내, 선택 초기화, 가용 시간과 내 예약 갱신을 수행한다.
- 예약 요청 실패 시 오류를 안내하고 선택·요약을 유지하며 처리 상태를 해제한다.
- 성공 후 목록 갱신만 실패하면 성공 사실과 새로고침 안내를 함께 표시한다.

#### `R-19` 내 예약

- 본인의 확정·취소 이력을 표시한다.
- 같은 날짜·같은 상태의 연속 슬롯은 하나의 카드로 묶고, 비연속 슬롯은 분리한다.
- 새로고침 후에도 저장된 예약을 확인할 수 있다.

#### `R-20` 취소 확인 UI

- 확정 카드에서 취소를 누르면 대상 일시·총 시간과 묶음 취소 안내를 표시한다.
- 돌아가기는 예약을 유지한다.
- 확인 시 해당 카드의 모든 예약을 취소한다.
- 실패하면 모달 내 오류를 표시한다.

#### `R-21` 취소 API

- 본인 단일 예약 및 ids 배열(중복 없는 문자열 1~9개)을 취소한다.
- 잘못된 배열은 400이다.
- 묶음에 타인·없는 ID가 포함되면 404이며 전체 취소를 수행하지 않는다.
- 이미 취소한 예약의 재취소도 성공한다.
- 취소에는 별도 시간 제한이 없으며, 과거 예약도 본인 예약이면 취소할 수 있다.

#### `R-22` 취소 이력·재예약

- 상태는 confirmed → cancelled로 변경하며 행을 삭제하지 않는다.
- 취소된 카드의 일시·공간·총 시간은 회색 취소선으로 표시한다.
- 취소 후 시간 조건을 만족하고 잠기지 않은 슬롯은 다시 예약할 수 있다.

#### `R-23` 관리자

- 관리자에게만 잠금·해제 버튼을 표시한다.
- 유효한 빈 슬롯을 잠그고 해제할 수 있다.
- 이미 확정 예약이 있는 슬롯의 잠금은 409이며 기존 예약은 유지한다.
- `slot`이 유효한 예약 시간 조건(R-11)을 만족하지 않거나, `blocked`가 불리언(`true`/`false`)이 아니면 400을 반환한다.



## 4. 저장·환경 요구사항
### `N-01` 예약 상태 저장
SQLite에 예약과 잠금을 저장한다. 서버 재시작 후 데이터는 유지한다. 부분 고유 인덱스가 동일 슬롯의 confirmed 중복을 방지한다.

### `N-02` 세션 쿠키·요청 보안
세션 쿠키는 HttpOnly와 SameSite=Strict를 사용한다. Origin 헤더가 있는 상태 변경 요청은 서버가 기대하는 동일 Origin과 다르면 403으로 거부한다.

### `N-03` 실행·테스트 환경
일반 서비스는 기본 3000 포트, 자동화는 3100 포트와 실행별 임시 DB를 사용한다. worker는 1개, 자동 재시도는 0회이며 실패 보고서·trace·스크린샷을 설정한다.

### `N-04` 예약 ID 발급
신규 예약 ID는 생성일(KST) YYYYMMDD와 날짜별 공통 순번을 연결한 `20260928-0001` 형태다. 슬롯마다 발급하며 순번은 최소 4자리다. 취소·서버 재시작에도 순번을 유지하고 예약 실패 시 발급을 롤백한다. 기존 UUID는 유지한다. 상세는 [설계 문서](design.md)의 예약 저장과 ID를 참조한다.
